GUIDE 02 · ORGANIZE YOUR WORK

Organize requests and environments

Keep related endpoints together so a useful request does not get lost after one test.

  1. Build a collection

    Use + Request for an endpoint and + Folder to group related requests. Rename items to describe the job they perform.

  2. Arrange the run order

    Move requests within the tree or drag them into a folder. A collection run follows the visible request order and reports each request separately.

  3. Create an environment

    Open Manage beside the Environment selector. Add named values such as baseUrl or apiToken, then mark sensitive values as secret so the interface can mask them.

  4. Use variables in a request

    Reference a variable with double braces, for example {{baseUrl}}/v1/users. Keep development, staging and production values in separate environments.

  5. Import an OpenAPI specification

    Open Data tools and choose Import OpenAPI. API Studio reads supported OpenAPI 3.x JSON or YAML files locally, then previews the operations and compatibility notes before you confirm. Choose a declared server and an optional destination folder. When a method and URL already exist, choose whether to skip, replace or append a clearly named copy.

  6. Set variables and authentication

    Path, query, header and server placeholders are imported as {{variable}} references. Add their values in the Environment manager. OpenAPI security schemes are not auto-configured, so add authentication headers or variables yourself.

OpenAPI import supports JSON/YAML OpenAPI 3.x only. Swagger 2.0, remote $ref resolution, automatic authentication setup, non-JSON request bodies and path/operation-specific servers are not imported; the preview shows compatibility notes. Import never fetches remote files or sends a request. Environment variables and collections are stored in this browser's site storage. Secret masking is a display and redaction aid, not encryption at rest.
